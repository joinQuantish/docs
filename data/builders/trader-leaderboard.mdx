---
title: "Builder Trader Leaderboard"
openapi: "GET /v3/builders/{code}/leaderboard"
description: "Rank the traders active through one builder by attributed volume, fills, trader-paid fees, active days, or recency."
---

This endpoint ranks wallets whose CLOB V2 maker orders were attributed to one builder. It supports 1-day, 7-day, 30-day, and complete-history windows.

This is a **builder-attributed activity leaderboard**, not a P&L leaderboard. A wallet's eventual realized or unrealized P&L cannot be assigned to one builder from order attribution alone. `pnl_scope` is therefore always `not_applicable_builder_attributed_activity_only`.

Each full outcome share contributes $1 of par notional to volume. Trader-paid fees are reported in six-decimal USDC units. They are not builder rebates, builder revenue, or P&L.

## Request

```http
GET /v3/builders/{code}/leaderboard
```

### Path parameter

| Parameter | Type | Description |
|-----------|------|-------------|
| `code` | string | Builder code as `0x` followed by 64 hexadecimal characters |

### Query parameters

| Parameter | Type | Default | Description |
|-----------|------|---------|-------------|
| `period` | string | `30d` | `1d`, `7d`, `30d`, or `all` |
| `sort` | string | `volume` | `volume`, `trades`, `fees`, `active_days`, or `recent`; `recent` sorts by `last_activity_at` |
| `order` | string | `desc` | `asc` or `desc` |
| `limit` | integer | `100` | Rows per page, from 1 through 100 |
| `offset` | integer | `0` | Rank offset, from 0 through 100,000 |

The fixed windows end on the latest successfully materialized UTC date. That can be the current UTC date, in which case the final bucket is a partial-day snapshot through `as_of`, not a claim that the calendar day has ended. `all` begins at the first retained builder-activity date.

`coverage.complete` means that every UTC date in the selected window has a successfully built aggregate row. `window.complete_through` is the latest date included in that contiguous window. The aggregate is normally refreshed about every 30 minutes. The endpoint fails closed with HTTP 503 when a required date is missing or the latest projected date is older than the previous UTC date; clients can use `as_of` when they require a stricter freshness threshold.

For a second page of 100 rows, keep the same filters and send `limit=100&offset=100`. Rankings use wallet address ascending as the deterministic tie-break, regardless of the requested metric order.

See [Authentication](/authentication) for key creation and [Rate Limits](/guides/rate-limits) for plan availability and current request limits.

## Common queries

```bash
BUILDER_CODE="0x4898df15ec6590495dc6c0fedf951ade3e64001d47f9caf44a64e86fc11959df"
BASE_URL="https://api.polynode.dev/v3/builders/${BUILDER_CODE}/leaderboard"

# Latest 1-day window by volume
curl -H "x-api-key: pn_live_YOUR_KEY" "${BASE_URL}?period=1d&sort=volume&order=desc"

# Latest 30-day window by attributed fills
curl -H "x-api-key: pn_live_YOUR_KEY" "${BASE_URL}?period=30d&sort=trades&order=desc"

# Complete retained history by trader-paid fees
curl -H "x-api-key: pn_live_YOUR_KEY" "${BASE_URL}?period=all&sort=fees&order=desc"

# Second 100-row page
curl -H "x-api-key: pn_live_YOUR_KEY" "${BASE_URL}?period=30d&limit=100&offset=100"

# Least active-day counts first
curl -H "x-api-key: pn_live_YOUR_KEY" "${BASE_URL}?period=30d&sort=active_days&order=asc"
```

## Response fields

| Field | Type | Description |
|-------|------|-------------|
| `builder_code` | string | Normalized builder code |
| `builder_name` | string \| null | Public builder name when available |
| `builder_logo` | string \| null | Public builder logo URL when available |
| `builder_verified` | boolean \| null | Public verification state when available |
| `period` | string | Resolved ranking window |
| `sort` | string | Resolved sort metric |
| `order` | string | Resolved sort direction |
| `limit`, `offset`, `has_more` | integer / boolean | Offset-pagination state |
| `window` | object | Inclusive UTC start and end dates used for the ranking; `complete_through` is the latest included date |
| `coverage` | object | Full retained date extent; `complete` means every date in the selected window has an aggregate row |
| `as_of` | string | Completion timestamp of the latest contributing aggregate; a current-day bucket is a snapshot through this time |
| `volume_scope` | string | Always `clob_v2_onchain` |
| `volume_semantics` | string | Always `outcome_share_par_notional`; one full outcome share represents $1 of par notional |
| `fee_semantics` | string | Explains that fees are six-decimal USDC paid by traders and are not builder rebates |
| `pnl_scope` | string | Always `not_applicable_builder_attributed_activity_only` |
| `data[].rank` | integer | Deterministic rank after the requested sort and an ascending wallet-address tie-break |
| `data[].wallet`, `data[].trader_address` | string | Same normalized trader wallet address |
| `data[].volume_e6` | string | Exact attributed outcome-share par notional in 6-decimal units |
| `data[].volume` | string | Decimal attributed outcome-share par notional |
| `data[].buy_volume_e6`, `data[].sell_volume_e6` | string | Exact signed-order-side attributed volume in 6-decimal units |
| `data[].buy_volume`, `data[].sell_volume` | string | Decimal signed-order-side attributed volume |
| `data[].trades` | integer | Attributed maker-order fills in the selected window |
| `data[].trader_paid_fees_e6` | string | Exact trader-paid fees in raw six-decimal USDC units |
| `data[].trader_paid_fees` | string | Decimal trader-paid fees in USDC |
| `data[].active_days` | integer | UTC days with at least one attributed fill in the selected window |
| `data[].first_activity_at`, `data[].last_activity_at` | integer | First and last attributed fill times in Unix seconds |

## Errors

| Status | Error | Meaning |
|--------|-------|---------|
| `400` | `invalid_builder`, `invalid_period`, `invalid_sort`, `invalid_order`, `invalid_limit`, or `invalid_offset` | A path or query value is invalid |
| `401` | authentication error | The API key is missing or invalid |
| `402` | payment required | The key's plan does not include paid V3 REST data |
| `404` | `builder_not_found` | The normalized builder has no metadata or indexed activity |
| `429` | rate limit exceeded | The account's shared V3 REST request limit was exceeded |
| `503` | `builder_trader_leaderboard_unavailable` | A required builder daily aggregate is incomplete or unavailable; no partial ranking is returned |
