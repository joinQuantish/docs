Returns a combo-only summary for a wallet. Use this endpoint when you want to inspect combo exposure separately from the standard wallet summary.

For an all-in wallet summary, call `GET /v3/wallets/{address}?include_combos=true`.

<OwnerAddresses />

## Request

```
GET /v3/wallets/{address}/combos/summary
```

### Path parameters

| Parameter | Type | Description |
|-----------|------|-------------|
| `address` | string | Wallet address or owner EOA |

## Example

```bash
curl "https://api.polynode.dev/v3/wallets/0x8f73711ac46f9e9c7d97196889603a52bc42bb9e/combos/summary" \
  -H "x-api-key: $POLYNODE_API_KEY"
```

## Response fields

| Field | Type | Description |
|-------|------|-------------|
| `open_combo_count` | integer | Open combo positions |
| `closed_combo_count` | integer | Closed combo positions |
| `balance_count` | integer | Total combo balance rows tracked for the wallet |
| `realized_pnl_usdc` | string | Realized combo P&L in USD |
| `unrealized_pnl_usdc` | string or null | Current unrealized combo P&L when available |
| `total_pnl_usdc` | string | Realized + unrealized combo P&L |
| `last_activity_at` | string | Last observed combo activity for this wallet |
| `win_count` | integer | Resolved combo positions the wallet won |
| `loss_count` | integer | Resolved combo positions the wallet lost |
| `resolved_count` | integer | `win_count` + `loss_count` |
| `win_rate` | string or null | `win_count` / `resolved_count` as a 4-decimal fraction (`"0.6964"` = 69.64%); `null` when the wallet has no resolved combo |

### Win and loss counts

A combo position is won or lost once its legs resolve: a YES position wins when
every leg wins and loses as soon as any leg loses; a NO position is the reverse.
The counts cover every combo position the wallet has held, all time, whether or
not it was redeemed. Open positions are not counted. To list the positions
behind the counts, call
[Wallet Combo Positions](/data/combos/wallet-positions) with
`status=resolved_win`, `status=resolved_loss`, or `status=resolved` (both).

### Owner address fields

Present only when you pass an owner EOA. See [Owner addresses](/data/overview#owner-addresses).

| Field | Type | Description |
|-------|------|-------------|
| `wallets` | array | The combined wallets, in a fixed order, each `{wallet, type}` with `type` one of `eoa`, `safe`, `proxy`, or `deposit_wallet` |

Counts and P&L are summed across the combined wallets, `win_rate` is recomputed from the summed counts, and `last_activity_at` is the latest of them.
