title: "Backtesting Overview"
description: "Estimate copying slippage from recent wallet fills with V3 Copy PnL."
---

Use V3 Copy PnL to compare gross trading cash flow with a fixed copying-slippage simulation over recent fills or an explicitly selected date window, with optional full-history calculation. Polynode computes the result from its indexed data.

| Endpoint | Purpose |
|---|---|
| [GET /v3/wallets/{address}/copy-pnl](/data/wallets/copy-pnl) | Calculate one wallet. |
| [POST /v3/copy-pnl/batch](/data/wallets/copy-pnl-batch) | Calculate up to 100 input wallets, with individual results and errors. |

The copier pays 2% more on buys, capped at 1 USDC per share, and receives 2% less on sells. Settlement cash flows receive no simulated slippage. Read the [calculation and coverage details](/data/wallets/copy-pnl#calculation) before interpreting the result: fees and opening inventory value are excluded, and open positions are not marked to market.

The default recent cap is 50,000 fills per wallet. Date filters, automatic history expansion with an explicit fallback, and strict full-history mode are available. Each response also includes separately scoped lifetime realized-PnL context with update metadata. V3 uses normal account REST limits without V2's five-second throttle. Results can be cached for 30 seconds, and large uncached batches can return individual deadline errors.

## Legacy V2

The [V2 single-wallet](/api-reference/backtesting/copy-pnl) and [V2 batch](/api-reference/backtesting/batch) on-demand endpoints are deprecated. Follow the [V3 migration notes](/data/wallets/copy-pnl#migrating-from-v2); the response and selection window differ.

The older BYOB tracked-wallet pool, snapshot, and leaderboard are separate legacy features. V3 Copy PnL does not replace or refresh them. Their historical references remain available in the Backtesting navigation.
